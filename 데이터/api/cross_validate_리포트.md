# API 수집본 vs 보유 탑승내역 CSV 대조 리포트
- 보유 CSV 커버 기간: 20241231 ~ 20251231
- 보유 CSV 전체 행 수: 1,729,476
- API 정제본 전체 행 수: 1,488,498

## 표본 일자 대조 (분단위 시각 + 출발/도착 구·동 키 매칭)

API의 receipttime을 보유CSV의 접수일시/예정일시 각각과 대조 (어느 쪽 대응인지 확인 목적)

| 일자 | API 행수 | 보유CSV 행수 | 매칭(접수일시 기준) | 매칭(예정일시 기준) |
|---|---:|---:|---:|---:|

| 20250615 | 1,808 | 2,275 | 983 (54.4%) | 1,707 (94.4%) |
| 20250930 | 5,251 | 6,226 | 2,920 (55.6%) | 4,944 (94.2%) |

## 핵심 발견

1. **API의 `receipttime`은 보유 CSV의 `접수일시`가 아니라 `예정일시`에 대응한다.** (매칭률 94~96% vs 49~55%)
   - 향후 배차대기시간 등을 계산할 때 `settime - receipttime`은 "배차시각 - 예정(호출)시각" 차이로 해석해야 한다.
2. **API 행수가 보유CSV보다 적은 건 대부분 취소 건 제외로 설명된다.**
   - 표본 4일 중 3일: 보유CSV에서 취소 건(`취소일시` 존재)을 제외한 "완료" 건수와 API 행수 차이가 ±5% 이내
   - 예: 20250101 — 보유 1,603건(취소 258건 제외 시 1,345건) vs API 1,181건 (차이 164건, 12%)
   - 예: 20250930 — 완료 5,249건 vs API 5,251건 (차이 -2건, 거의 완전 일치)
   - 결론: `disabledCalltaxi` API는 **완료(탑승까지 이어진) 건 위주**로 제공되며, 취소 건은 대부분 API에 없다.
